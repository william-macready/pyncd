## 0. Execution protocol

Per task: (1) implementer works in the worktree, builds only the modules it touches (`bash <wt>/leanncd/scripts/lake-build.sh <wt>/leanncd <Module>`, absolute paths, background, no sleep polling, never read a whole log: `rg -n "error|✖|jobs"`), commits once;
(2) controller runs the full `Tests` build; EVERY task leaves the tree fully green (flips are made in the task that causes them): expected `Build completed successfully`, 8825 jobs (+ new test modules, if any, counted in the report), zero red targets, no `sorryAx`;
(3) any red target, any unexpected value, any pre-existing expectation changed beyond the task's listed flips is a finding: STOP and report, do not edit expectations to match. Rule 6: <= ~60 tool calls and <= ~250k context per dispatch; a task that will exceed it is split BEFORE dispatch.
Each flipped expectation is recorded old -> new with its reason in the record (`additive_s3bii_record.md`, created at close-out). No `File.lean:NNN` citations in anything shipped. Batch AGENTS.md edits into T5.
Hand mutation = break production, see the named fixture fail, restore byte-identically (`git diff` empty for the file), observed failure quoted in the commit body. No manifest unless a task reports an entry that is non-redundant; the controller then adds it to `papers/additive_s3bii_mutations.json` and runs `--task` once.
