### F1 [Minor] Summation order is SCHEDULE order, not source order; the decision note and fixture V5 say "source order"
CONFIRMED (traced). `desugarMultiWriters` (`DSL/Pipeline/Collect.lean`) numbers writers in schedule order, as its own docstring and plan §2 say. On the surface path, schedule order comes from `topoSort` (`ScheduledValidation.lean`, `topoSortFuel`: stable Kahn, `findIdx?` over `remaining`). It moves a writer that is not yet eligible behind later writers. Decision note §C.3 ("Writer k of T (1-based, source order)") and `test/Eval/CollectEvalTest.lean` V5 ("writers are collected in SOURCE order") are only true when no writer has to wait.
Scenario (surface, explicit f64):
```
T[i] := V[i]      -- source writer 1, reads V, which is defined later
T[i] := A[i]      -- source writer 2
T[i] := C[i]      -- source writer 3
V[i] := B[i]
```
`topoSort` gives `T:=A, T:=C, V:=B, T:=V`, so `T#1=A, T#2=C, T#3=V`, and the collector folds `((0+A)+C)+V`. Source order would fold `((0+V)+A)+C`. With A=1e16, C=1, B=-1e16: schedule order gives 0, source order gives 1. Both backends consume the same collected schedule, so the reference and the checked plan still agree bit for bit (the plan's dense fold mirrors the reference: same op/identity pair, starting from +0, `Dense.lean`). Spec §19.2 says the order of the summands has no semantic meaning, so this is not a soundness defect. It is a wrong claim in the record, and anyone reading V5 or §C.3 could pin f32 bits on it.
Fix: change §C.3 and V5's comment to "schedule order (= source order unless `topoSort` must delay a writer)". Optionally, add one fixture that pins the delayed-writer numbering (`T#1` = the source's second writer).

Hunt items with nothing to report:

1. Collector equality: no defect. The collector reads `T#k[x0..xn]` and writes `T[x0..xn]` position for position, so the result depends only on each `T#k` having T's coordinate space. The UID-per-position check guarantees that. A transposed writer is either rejected (distinct UIDs) or impossible (a repeated UID is diagonal, so it becomes a scatter and is rejected `multiWriterScatter`). Each writer keeps its slots, nonlinearity and term-local contraction unchanged, so `T#k` = V_s. A self-read can never be ready, so it fails `cyclicDataflow`. Duplicates count twice (2X). For a predicate, the collector uses the same associative `Combine.bool` as each writer, so grouping holds even for non-{0,1} reads. `.freeNorm` is degraded by `producerSlots` on the collector only. Zero extents give empty folds. The empty-sum rule is not realized and is recorded in decision note line 307.
2. Readiness: no defect. `outputs ⊆ writes`, and `publications` dedups within each node, so `emitted.count r ≤ #writers(r)`. When there are 0 or 1 writers, `count == #writers` is exactly the old `contains ∨ unwritten`. Eligibility is therefore identical at every step of `topoSortFuel` and `isTopoOrdered`, so single-writer emitted order is unchanged and no legal single-writer schedule can deadlock. A reader is released only after every publishing writer. Scratch never publishes, and `.scanPre` publishes `[nm]`. On validated input, the post-collection `isTopoOrdered` assertion cannot fire: the collector sits after the last writer and before every reader.
