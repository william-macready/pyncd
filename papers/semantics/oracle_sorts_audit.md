# Oracle per-tensor sorts and coverage: read-only audit

Status: AUDIT, 2026-10-25, base main 9507c5af. Read-only (no build run, nothing observed at run time: every claim is code/doc reading unless it says "observed"). Cites identifiers, no line numbers.

## 0. Headline findings (read first)

H1. **The Source language the oracle accepts has NO bool, NO Iverson, NO unary function, NO nonlinearity, NO affine READ, NO scan.** `admitStatement` / `admitAffineWrite` (Admission.lean) refuse: `rhs.nonlin != .identity` (`unsupported .nonIdentity`), `Factor.iverson` (`unsupported .iverson`), `Factor.unaryFn` (`unsupported .unary`), read indices other than a bare axis (`readIndices`: `unsupported .affine`), and `tensorDecl` (Adapter.lean) refuses `Decl.predicate` (`unsupported .predicate`) and `.iter` (`.iteration`). The sorted entry only rewrites `agg := .sum` for max/min statements; everything else still applies. The oracle's term is a pure monomial: a product of BARE-index reads (`Oracle.termFiber`: `product := product * value`), the empty product is the carrier `1`, and an out-of-range read is an ERROR (`Oracle.lookup` / `offset` -> `coordinateBound`), never a pad. Writes may be affine (`WriteForm`, `Oracle.destination`; out-of-range write is `writeOutOfRange`), and scatter is admitted (`admitAffineStatement`).
Consequence: **the cast cells involving bool, the Iverson value, the OOB-pad value, the unary-OOB rule and the nonlinearity-neutrality rule are not just "unmodelled in the oracle", they are unexpressible in the Source admission.** Giving them four-leg parity is NOT a change to the oracle value type only; it is also a change to Adapter (`predicate` decls + bool input buffers), Admission (affine/const/shift reads, `iverson`, `unaryFn`, nonlin), `RawSemanticConnection`/`Correspondence` (the proof layer is keyed to `StatementFields`/`TermFields`, which pin `agg = .sum`, `nonlin = .identity`, bare slots), the Core leg (`runSourceAt` is a monomial semiring program), and the profile (`checkSortedProfile` bounds products of reads only). See section 2 and the decisions in section 6.
H2. What IS expressible today, per-tensor-sort, with the existing Source language: statements `max`/`min`/`sum` over bare-read monomials into f64 tensors; reads across sorts (real <-> tropical identity, max<->min refused by production); top-level multi-writer groups with collisions combining via the carrier; neutral-copy statements (one read, no contraction, bare free slots); affine writes (colliding LHS neutrality, `669ce30e`) and scatter. So the **mutation bar can only be met for the subset of defects whose program shape lies in that sublanguage** (section 3); the rest need the language widening (a different, much larger slice) or must be kept as production-only hand fixtures, honestly labelled.
H3. `selectCarrier` is NOT the only single-sort gate: `checkStructure` (NumericalProfile.lean) requires every used tensor `elementType == .f64` (`usedDType`), and `selectCarrier` itself refuses mixed element types (`mixedElementTypes`). Undeclared `tensor`/`linear` are `f32` in `tensorDecl`, so every fixture needs `typedTensor .f64`.
H4. `runNative snapshot (sorted := true)` does NOT select a carrier. It only calls `admitSourceAffine snapshot true` and then runs the ORIGINAL TL program through `legacyWithInputs` / `checkedWithInputs`. So **both native legs already take mixed-sort Source programs unchanged**; only `admitSourceSorted` (selection) and `Oracle.runWith`/`runSourceAt` (one `K`) are single-sort. See section 2.

Code-only facts about the cast cells (candidate silent decisions):
- C1. The cast is selected by the SOURCE's DECLARATION (`isPredicateDest src` / `isBoolSlot`), not by `algebraOf`; `algebraOf` is used only to REJECT. Equivalent today only because a tensor is bool iff declared `predicate`.
- C2. `checkSortCasts` checks only destinations that HAVE a map entry (`algebras[nm]?`). A real/bool multi-writer group has none, so reads INTO such a group are unchecked. For Source programs this is moot (the cast table has no rejection into real, and a bool group cannot occur); it would matter only for a bool-destination group reading a tropical tensor (not verified, outside the oracle).
- C3. A read under `unaryFn` is never rejected and never cast (takes real input): `checkSortCasts` `| .unaryFn .. => pure ()`; a tropical source under unary into a bool/other-tropical statement is accepted (this is the F2 "cast bypass" the user parked; also one-copy bypass D3).
- C4. A scan-state or multi-writer READER cell: the source sort used is `algebras[src]?.getD (env.declAlgebra src)`.

Does the checked-plan / legacy leg already handle mixed programs in the sorted path? Verified by reading: nothing in `runNative`, `legacyWithInputs`, `checkedWithInputs` or `observeBindings` looks at `agg`; production accepts mixed-sort programs since S3b (`CollectPlanTest`, S3b-ii T4), so a mixed Source snapshot that passes `admitSourceAffine true` is run by both native legs and would be compared against profile cells. NOT run (read-only audit, unobserved): that nothing in `legacyWithInputs` / `prepareNativeInputs` rejects it. A design task must observe one mixed fixture on the legs before anything else is built.

Does admission accept mixed programs once selection is bypassed? Yes for everything in the Source sublanguage (see H1), including max/min SCATTER and affine writes (`admitAffineStatement` with `sorted := true` maps scatter and assign alike). A8 (`tropicalNonlin`) is unreachable: `admitStatement` already refuses `nonlin != identity` for every sort, so there is no Source cell for it. The `sortSelection (mixedSorts ..)` diagnostics of today are `Except` errors, not classifications.

Minimal universal value type: `ExtVal` (`fin q | negInf | posInf`) IS sufficient and already the shared observation type: real cells are `fin q` only; max-plus cells are `fin q | negInf`; min-plus `fin q | posInf`. The oracle ops on it must be re-stated by hand per sort (for independence, see section 5), with `+inf`/`-inf` flowing through tropical `+` as the tropical zero absorbs (`-inf + x = -inf` in max-plus, `+inf + x = +inf` in min-plus; a `-inf` in a min-plus statement is not a legal value and must be a refusal). The one unsolved cell: a real STATEMENT reading an `±inf` cell (a tropical tensor with an unwritten cell read into a real product): production gives IEEE `inf`/NaN arithmetic, `ExtVal` has none; recommendation: classify as `unsupportedNumericalProfile` (a new `Unsupported` constructor) rather than model it (decision 6.5).

Per-tensor sort derivation in the oracle must be restated from the spec (section 1(a)), not read from `Stmt.isSortNeutral`/`writerSort?`, because Source statements are `Stmt` values and calling the production helpers is the obvious shortcut (section 5).

Estimate, heterogeneous oracle path with Core leg option K3 or K2: Sorts.lean +120, Oracle.lean +90, NumericalProfile +60, SortedDifferential +110, Admission +40: about 420 lines of library, plus ~30-45 new test guards. With option K1: add 600-1000.

## 3. Defect catalogue for the mutation bar

Method: every finding in the S3b final reviews (`additive_s3b_review_final_semantics.md` M1/m1-m6, `..._rejections.md` F1-F5), the S3b follow-up batch (`additive_s3b_record.md` sec 10, `additive_s3_followup_review.md`), the S3b-ii final reviews (`additive_s3bii_review_final_semantics.md` F1-F5, `..._rejections.md` F1-F8) and the minors review (`additive_minors_review.md` m1-m7, n1-n3) was classified. "Found only by review" = the defect or unpinned behaviour was not caught by the slice's own tests. Docs-only and comment-only findings (S3b F3/F4, S3b-ii F6/F7, minors m1/m2, n1-n3) are not defects and are omitted. "Expressible" means: a program the CURRENT Source admission accepts (H1: bare-index monomials, f64, no bool/Iverson/unary/nonlin/affine reads/scan; affine writes and scatter allowed) exhibits it, so a heterogeneous Source oracle could in principle flip a classification. The mutation bar needs a classification to flip: for refusal-type defects that needs a new "oracle-predicted refusal" outcome (decision 6.2), since today a refusal is an `Except` error, not a `SortedClassification`.

### 3.1 What the bar can honestly cover

## 5. Independence risk

A naive oracle would be written by reading `Stmt`s and asking production what sort they have. The production helpers a heterogeneous oracle or its rule predictor MUST NOT call (each one is also a mutation site, so calling it makes the mutation invisible):

- Sort and neutrality: `Stmt.isSortNeutral`, `Stmt.ownAlgebra?`, `Stmt.algebra`, `AggOp.algebra`, `SortAlgebra.isTropical`, `SortAlgebra.stateAgg`, `DeclEnv.declAlgebra`, `LHSSlot.axisUids` (and `Factor.read?`, `Stmt.slots`, `Stmt.lhsName`, `idxAffineForm` only as pure structure accessors: acceptable, `oracleNeutral` in `ScanUnroll` uses its own `oracleIdxUids`/`oracleSlotUids` instead and that is the better precedent).
- Votes and groups: `writerVotes`, `writerSort?`, `scanStateSorts`, `scanStateAlgebra`, `scanStateStmts`, `scheduleAlgebras`, `checkSortCasts`, `checkWriterGroup`, `writerGroups`, `slotsBecomeScatter`, `collectorStmt`, `desugarMultiWriters` (mutation targets R1, R6, R10, R11, R12, R16).
- Values: `Combine.*`, `combineFor`, `boolReadCast`, `gatherCast`, `maxNaN`/`minNaN`, `ContractionAlgebra` tables, `ReadPlan.boolToTropical`/`realToBool` (R2, R3, R8, R14).
- Source-layer sharing that is ALREADY accepted and fine to keep: `WriteForm`/`destination` (write coordinates), `coordinates`, `lookup`; they are not sort logic.
- A hidden copy channel: `Oracle.Carrier.admits`/`selectCarrier`/`sortKeys` encode "agg -> sort" a third time; a heterogeneous path must not extend `sortKeys` to derive per-tensor sorts (it keys on each statement's own agg and so counts a neutral copy as a voter: the exact opposite of the production rule).
- The existing `ScanUnroll.oracleNeutral` is a third statement of neutrality (test side, used for scans, public). Reusing it for the group rule is cheap and acceptable (it is already independent of production and pinned to it by the `neutralShapes` agreement guard); but note it is a THIRD copy to keep in sync, and the S3b final review (rej F5) already recorded that it initially copied production verbatim, which is how M1 slipped through.

Guards (agreement tests over an enumerated corpus, modelled on `neutralShapes`/`oracleNeutral`, which is itself the only such guard today):
1. Neutrality and votes: enumerate writers = {sum, max, min} annotation x shape {bare copy, copy with contraction, relu copy, Iverson-only copy, colliding-slot copy `Out[i+j]`, affine single-axis `2*i+1` copy, predicate destination} (about 21 writers); all ordered pairs (441) and a sample of triples; assert `predict(group) == production(group)` where production is `writerSort?`/`checkWriterGroup`/`desugarMultiWriters` accept-or-error plus the agreed sort. Pure, no build of values. Kills R1, R6, R10(partly), R11, R12, R16 and the vote-rule arms of R9.
2. Cast table: all 4x4 (source sort x reader sort) one-read programs, assert accept/refuse vs `checkSortCasts` and the refusal identity (`sortCastUnsupported dst src`); plus the laundering pair to pin decision A.
3. Collection ⊕: for each sort the collected value of a 2-writer group on a small value grid vs the checked plan/reference (a value guard, cheap: reuse the four-leg run).
4. Corpus self-check: assert each mutation row of section 3 that is claimed expressible has a corpus entry that distinguishes it (the follow-up record admits the contracted-axis mutation was caught by hand-built shapes only: a corpus with no single contracting read is vacuous for that conjunct).

## 6. Decisions only the user can make

1. **What the bar covers, and where the independent rules live.** Section 3.1: the value oracle can only express R10, R11, R16 (+ cast/collection rows); R1, R12, R6 need a syntactic rule predictor; R3, R2, R14, R15 are outside any exact-rational oracle. Options: (a) value oracle only, accept that the mutation bar covers 3 defects; (b) value oracle + independent syntactic rule predictor and agreement corpora over the full AST (recommended: the corpora are cheap and kill 9 of 12 real defects); (c) widen Source admission (bool decls, affine/const reads, Iverson) so pad/bool rows become expressible: a separate slice (Adapter/Admission proofs keyed to `StatementFields`/`TermFields`/`tensorDecl_classifies`), not recommended here. Recommendation: (b), bool stays OUT of the oracle's sorts (it is not expressible); the predictor models bool syntactically only. Placement recommendation: put the rule tables and the heterogeneous evaluator test-side (`test/Semantics/`, beside `SourceSortedDifferentialTest`), so the independent rules cannot be imported by production and no library rebuild is needed to add them; library edits only where `compareMixedSource` needs a public hook. Cost difference: test-side saves the library rebuild per task; the mutation cycles rebuild the library anyway (they mutate `DSL/Ast.lean`).
2. **Classification of production refusals.** Today a refused cell is an `Except` error or `nativeFailure`. For a mutation to flip a classification when production starts refusing/accepting a group (R10, R11, R16) the harness needs an oracle-PREDICTED REFUSAL outcome carrying the expected production `CompileError` constructor, compared with the legs' compile failure. Recommended: add `SortedClassification` constructors at the end (`refusalParity (expected : String)`, `refusalMismatch`), leaving the existing seven and their printed forms unchanged (63 guards in `SourceSortedDifferentialTest` print them). Option: encode as `referenceUnavailable`: rejected, it conflates "oracle cannot evaluate" with "oracle predicts production refusal". Cost: about +40 lines and the choice of what counts as the same refusal (constructor name only, recommended; payload names are brittle).
3. **Core leg for mixed programs.** The Core is sort-indexed but the Source layer is wired to `Unit`. K1 (a real heterogeneous Core leg: tensor table carries sorts, `semiringOps` dispatches, casts as `Registry` ops): 600-1000 proof-bearing lines, more than this slice. K2 (stratified: run the existing single-K Core leg once per TARGET in dependency order, with already-computed tensors as rational inputs; legal only while intermediate cells are finite): about 100 lines, weaker (it does not check cross-statement scheduling of one Core program). K3 (no Core leg for mixed programs, three-leg parity with an explicit `core not run` marker; the mixed rows keep four legs only when single-sort). The user's stated bar says four legs; recommendation K2, and say so out loud in the record; K1 only on request as its own slice.
4. **Non-finite cells read by a real statement.** A max-plus tensor with an unwritten cell is `-inf`; read into a real product (`0*-inf`) production gives IEEE NaN/inf, which the exact oracle has no meaning for. The spec says only "real <-> tropical identity". Recommend `unsupportedNumericalProfile` (new `Unsupported` constructor `nonFiniteIntoReal`), excluded from parity rows, rather than modelling IEEE in `ExtVal` (cost +10 lines vs about +60 and a new silent decision).
5. **Whether the oracle encodes cast-rejection decision A.** An independent cast table forces a stance: refuse the direct max-plus -> min-plus read (as production) and accept the laundered copy (as production), or encode option B/C. Recommendation: encode A exactly as decided 2026-10-24 and add one pair of rows that pin it; if A is ever revisited, those two rows flip together. Cost: 2 rows.
6. **Scope of copy-form groups and corpus extent.** Copy-form groups with bare free slots are in (R11). Groups with an affine or scatter writer are production-refused (`multiWriterScatter`, B5 non-goal) while the typed oracle would just sum them: the heterogeneous harness must PREDICT that refusal or every such program shows as a false `nativeFailure`; recommend including the one-row refusal (cost +2 fixtures). Corpus extent recommendation: about 35 four-leg/refusal rows (12-16 re-expressed, the rest new) plus the 441-pair vote corpus and the 16-cell cast corpus (guards, no builds of values).

## 8. Stale or misleading claims in the brief

1. "Carrier.real.admits ... for ANY element type, i.e. bool/predicate destinations are computed as real in the oracle today": the first half is right (`fun a _ => a == .sum`), the second is misleading. `TensorElementType` is `f32 | f64 | complex64 | complex128`; a predicate destination never reaches the oracle because `tensorDecl` (Adapter.lean) refuses `Decl.predicate` (`unsupported .predicate`), and `checkStructure` additionally requires every used tensor f64. There is no bool in the oracle to "compute as real".
2. "the oracle has no ... Iverson/pad constants of the READER's sort": true but incomplete. They cannot occur: `astRead` refuses `Factor.iverson` and `Factor.unaryFn`, `readIndices` refuses any non-bare read index, so an out-of-range read cannot be expressed and `Oracle.lookup` treats it as an ERROR (`coordinateBound`), not a pad. The same holds for nonlinearities (`StatementFields` pins `nonlin = .identity`, `agg = .sum`).
3. "Existing mutation-manifest mechanics: `papers/semantics/*_mutations*.json`": the additive-series manifests live in `papers/` (`papers/additive_s3b_mutations_post.json`, 49 entries; also `additive_s2a/s2b/collection_slice1`); `papers/semantics/` holds the older plan-layer ones. There is no S3b-ii manifest (it ran Full-lite with per-commit hand mutations).
4. "`selectCarrier` picks ONE carrier ... a mix is `SelectionError.mixedSorts`": also `mixedElementTypes` and `noCarrier`; and selection is not the only single-sort constraint (`checkSortedProfile`'s weaker tropical bound, `coreTensorsAt`'s single `K`, `checkStructure`'s f64-only).
5. "Neutral writers abstain beside non-neutral ones" holds for groups and scan states, but a SINGLE-writer name uses its OWN annotation in `scheduleAlgebras` (`s.algebra env`, no abstention), so a lone neutral `maxreduce` copy `T[i] := maxreduce(X[i])` makes `T` max-plus. The oracle's per-tensor rule needs both arms.
6. "S3b-ii records ... parked list line ~38": it is section 4 of `additive_s3bii_record.md` (correct), but the record itself says the all-annotated Bellman programs already have `fourLegParity` on the oracle: the typed path covers homogeneous groups; only copy-form and mixed groups are `mixedSorts`.
7. The brief's "defects ... neutral-with-nonlinearity (M1/F1) ... cast defects, Iverson values, padding ... copy-form/writer-vote defects, colliding-LHS neutrality (669ce30e)": colliding-LHS neutrality (R6) has NO observable program shape at all (commit body and S3b-ii record agree); "Iverson values" were not a review-found defect since S3b (the Iverson constants were part of T2 and killed by `T2-M3`/`T2-M4`); there were no review-found CAST defects since S3b other than the decided F2 laundering and the unpinned NaN/-0.0 conventions (R2, R4, R14).
8. The Core leg is described as one `runSourceAt` over a single `K`; note the semantic core is already sort-indexed, so per-tensor sorts there is a Source-layer wiring problem (Unit everywhere), not a Core redesign (section 2).
9. Production cast cell "bool -> real" is in the spec table (`additive_production_decision_note.md` A7) but unreachable from Source; "tropical -> real" is "identity on values" in the spec, silent on what a `-inf` means inside real arithmetic (decision 6.4): a spec gap, not a code decision.
